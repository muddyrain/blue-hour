# AIRSTRIKE-02 Windows 隔离对照

基线为已合入 #40 的 `728b5f0a467651653c62e526132fc2a6e271a10e`。固定 Godot 4.7.2、Windows 11、GL Compatibility、i5-12400F 与 RTX 3060。修前仅加默认关闭的计时点。每条空袭路线在同一份已认证快照上恢复，修前和修后核对快照字节、地图、镜头和落点。每组首个样本来自新进程，随后在该进程用同一快照做 5 个热态样本。

实际窗口收到左键至包含冲击的首个 `frame_post_draw`，全程关闭录像与像素回读。计时覆盖引擎渲染完成，物理输入和显示器呈现另属验收层级。

FreezeProfile 的规划、读链和认证区间有嵌套，表中值各自统计。热态每次复用 4 次导航，落点、可达性、遮挡和命中仍逐项校验。泵站和旧生成版本沿原导航路径。急救实时和冻结回放使用同一射线判定，修后隔墙 5 秒内生命和可用次数保持原值。普通热态与打断热态均满足中位数 ≤250 ms、最大值 ≤400 ms。冷启动和单次急救仍主要等待收据确认。此次急救整步 p95 和最大值略高，规划本身的重建成本已减少。

实际命中后确认伤害和一次冷却。最小缩放下非法落点有提示且不扣冷却。写入失败时生命和冷却保持原值，冲击等待成功确认后才显示，重试同一请求只入账一次。尖啸打断后推进至原释放时刻之后，增援为 0。新进程继续读回空袭冷却和急救已用，Q 独立冷却，重复归航确认保持同一收据。M33 旧档继续时恢复相同武器实例、弹量和战场指纹。
