# M5-ANIM-02：普通僵尸动作稳定性

普通僵尸的贴身显示偏移会在目标跨过逻辑脚点时反向，造成36显示像素的跳变；角色的逻辑位置没有相应跳跃。方向临界角的微小扰动还会逐帧切换图集列，单tick导航停顿会把步态时钟清零。这三个问题分别在原Expedition场景及同一FieldActor的受控输入中复现。

## 实现边界

仅在ActorVisual的普通僵尸分支处理：

- 方向保留5度滞回，真正超过原22.5度边界加5度时才换向；MotionAtlas.octant()的公共映射不变。
- 小于一个原步态帧（1/9秒）的停顿保留步态相位和画面；持续停止仍回到idle。普通僵尸原9fps及[1,2,3,2]序列不变。
- 贴身显示偏移以96显示像素/秒追随原目标，60Hz下每tick最多变化1.6像素。原42像素留距计算与18像素上限不变；攻击/受击的小幅位移仍保留。

新增值均为PROJECT_TEMP显示参数。幸存者的瞄准、枪口和步态路径，以及rush/heavy分支保持原行为。FieldActor、AI、战斗判定、移速、HP、伤害、碰撞和资源图集均未修改。

normal_full.png为5×8、每格288×288，与现有裁切一致。逐格检查覆盖五个存储方向和八种动作（左向由镜像派生）；行走帧脚底高度差为1–2源像素，没有发现越格或截脚证据。本轮不重画、不重定位PNG。脚部摆动、四帧步态与45度离散朝向仍属于动画原型。

`_walk_rest`与接触偏移缓存只服务当前画面，不增加存档字段或版本。原快照中的时钟/朝向继续使用；恢复时缓存从当前几何初始化，不承诺恢复过渡中间帧。没有改写收据、哈希或拒绝规则，动画验收不替代P0存档安全矩阵。

## 验证与限制

Godot 4.7.2.stable.official.ed1daf0bf，macOS原生GL Compatibility。同一普通僵尸依次完成直线及短停、反复转向、靠近并跨过接触目标、攻击/受击/恢复移动四组输入；修复前后各连续16秒。另在原Expedition的AI、导航、近战与射击链中各录制连续10秒。录像通过MovieWriter以固定60Hz生成，不是OS物理键鼠或显示器帧时间测量。

| 同条件对照 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 四组中的贴身最大单tick显示偏移 | 36px | 约1.6px |
| 120帧临界角扰动中的列切换 | 119 | 0 |
| 三次单tick停顿导致的步态重置 | 3 | 0 |
| 原游戏600tick中的大于10px显示跳变 | 2 | 0 |

四组960tick和原游戏600tick的逻辑位置、实际速度及生命结果逐项一致；原游戏5个战斗事件（四次近战及一次射击）完全一致。攻击/受击位移保留，因此原游戏修复后最大显示变化为3px，不应将1.6px说成所有姿态的总位移上限。

公开入口`python3 tools/godot.py check`加入`animation/normal_stability`回归；定向17项与既有动作505项通过，公开14组检查通过。检查仍报告生产门禁BLOCKED及P0 PARTIAL。原始逐帧记录、失败驱动、截图和前后连续录像仅保存在忽略目录及本轮私有审阅包中，不进入公开仓库。

本轮结论：Mac受控原生场景通过；**Windows-NOT-VERIFIED**。未制作或验证新的Windows包，也未完成自然任务全程、不同刷新率、OS物理输入或完整持久化矩阵。P0-RECORD-HASH-01保持PARTIAL / NO-GO-PRODUCTION，正式默认入口不切换；M5-ANIM-02作为独立本地提交，未取得新的主线审阅或发布结论。
