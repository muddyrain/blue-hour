# M6-ROGUE-02 · 任务目标与行动差异 V1

四种任务在卡片、真实交互、紧凑 HUD 与冻结归航结果之间使用同一权威描述。每次从合法池中取三个不同类型的行动，同日浏览、维修、配装和重启不重抽；下一天重新生成。规模与奖励/敌人强度不相乘。沿用八类建筑、三档规模及三类道路；装备行动选有实际仓库/修理铺的兼容主题，不承诺纯住宅区会有仓库。

## 玩家流程

| 任务 | 主目标与完成事实 | 可选行动 |
| --- | --- | --- |
| 食物补给 | 绑定1—2个真实超市、便利店或餐馆食品站点；搜完标记点并成功归航 | 自选顺序，其他成员继续移动/交战；可只做部分后撤离 |
| 装备搜寻 | 在真实仓库/修理铺的主要武器站点取得原唯一武器实例并归航 | 其他钱粮点独立可搜；结算不另造武器 |
| 幸存者救援 | 原候选池的真实目标，接近和10秒援救后立即入队/自动参战；目标生还撤离才完成 | 加入后 HUD 改为带其归航；目标阵亡走原永久死亡政策，其余人可撤离；编制满/无资格者不生成救援 |
| 空投回收 | 在合法可达空地回收标记箱，按原工作规则推进约12秒，带回实际所得并归航 | 完成后直接集合或继续搜刮，不要求清空敌人 |

金色入口圈/指示标区分主目标与普通站点。空投使用必要的原创向量箱、信标和小进度条，没有新增外部图片素材。任务卡列名称、主目标、规模/主题、可搜获上限和实际风险；不显示未实现事件/难度标签。

归航预览和营地最近结果分别显示“完成主目标”“提前撤离未完成”或救援对象阵亡，以及实际所得。任务失败不禁止存活队员归航。没有任务额外奖金，钱粮、武器、口粮、成长和死亡继续由原 owner 结算。食品来源预留后，所有站点拆分同一个总预算；装备和空投使用货币4—7、食物0—2、武器1的首版 PROJECT_TEMP 范围。

## 空投的一次性压力

参数集中于 `TaskActions.PARAMETERS`：工作基准12秒、最多2名普通感染者，模板版本1、来源 PROJECT_TEMP。原个人搜集 Trait 仍应用；不更改基础移速、HP、伤害、接触、饥饿或巴士状态机。

首次实际到达并开始工作时，Expedition 同步记下 `started` 与两个有界尝试的实际结果（spawned/capacity/no_safe_point、生成身份）。沿用原 `_spawn_enemy`、合法边缘候选、可见性、队伍距离、间距、通路和容量规则；以空投位置选择较近的合法候选，额外保证距箱/工人的安全距离。晚间也只生成原普通感染者，不形成补生债务。

再点取消、换点、暂停或新进程恢复都保留同箱工作进度与触发事实。死亡中断采用原工作规则；已触发状态仍保留。敌人仍由原战场 actor/击杀事实解释，回收仍由 WorldSites/WeaponInventory 产生实际携带。没有第二套事件保存器、复合掉落 owner 或通用事件池。

## 版本与认证边界

新任务描述 **V4 / template_version1**，任务规则 **data_version5**，途中世界 **version6 / M6-ROGUE-02-1**。描述稳定绑定 seed/day/slot 的 task_id、目标站点/成员和参数；地图继续使用已审 NeighborhoodLayout V3 几何算法，但新任务有独立种子命名空间。选定后不重抽。

V1/V2/V3 描述、原 CONFIG、布局解释和历史哈希均保留各自分支。V3/规则4/世界5途中可按原快照兼容继续；V1/V2及更旧不兼容途中保持原消费前拒绝、代次与原件保护。旧完成营地可保留身份、资源、成员、训练和装备后进入新任务。

新世界与报告增加严格 `task_event`；未知字段、目标错配、预算/版本改动、工作却撤回触发、非法增援身份均拒绝。任务结果从真实站点、携带武器和加入/成员生还事实计算，保存在111的 `last_day.task`（摘要版本1）；EnemyState先校验该扩展再作只读旧结构投影，旧 schema 的 last_day 白名单不放宽。结果认证再次核摘要与真实报告一致。旧程序不能读取包含该新摘要/规则的进度，不向旧程序回写。

ReceiptJournal R1完整原文身份缓存和精确编码未修改；新字段包含在完整原文/规则/世界指纹中。旧证明不能认证修改后的目标或模板；新进程重新认证全链。原 READY/ACK、冻结成功后才登车、预览后明确确认、保存失败阻止新出击与唯一结算保持。

## 本轮验证边界

仅当前 Mac、固定 Godot4.7.2 / GL Compatibility。数据、严格合同、暖缓存篡改、跨 PID 空投、实际部分收益、四模板正常完成、提前撤离、救援生还/阵亡、保存失败重试、V3旧途中与旧完成样本、两人/四人 HUD 和公开 check 均按定向范围验证。死亡负例使用既有隔离夹具抑制指定对象开火，其余因果由实际导航、普通敌人和原死亡写者推进；不作为自然难度或平衡结论。

原生画面来自后台测试进程的1280×720 SubViewport；进程内 AppKit 激活守卫仅用于阻止抢占前台，外部采样核前台 PID。正常流程可加速自动推进，最终影片每编码帧推进1/30秒、30fps播放，明确标为1×模拟实机片段；无声，不代表物理键鼠、人工手感、显示 FPS 或发行包验收。

不重复 Windows、不导出跨平台包、不重跑未改的全量锁/强杀/历史矩阵。正式视觉与生产门禁仍 **BLOCKED / NO-GO-PRODUCTION**；任务候选成功不代表正式版完成。实际结果与失败索引、冻结 SHA 和轻量私有审阅 ZIP 见本轮交接。
