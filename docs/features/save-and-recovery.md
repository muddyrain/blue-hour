# 保存、暂存与可靠性边界

本文描述 **M5-ANIM-01及P0-RECORD-HASH-01候选** 的实际边界。新收据精确传输已在macOS验证原极小浮点暂存；**Windows和完整历史矩阵未完成，正式生存仍BLOCKED / NO-GO-PRODUCTION。** 动画GO和公开安全审计通过不能解除该门禁。不要用本原型承载唯一的重要进度。

## 新旧入口分开

普通默认保留原双人旧旅程及既有v1–v4到v5的迁移、原件归档边界。新成果通过[111隔离入口](README.md)创建独立本地进度；111不自动转换旧v5/早期隔离档，不把108等旧名册静默改成新规则，也不重抽属性。继续时使用同一隔离目录，不能拿真实玩家唯一原件做测试。

旧途中世界依赖当时的武器、资源、构建及规则指纹，不兼容时明确拒绝。特别是旧武器参数下的暂存须由对应旧包完成；不改版本号或放宽兼容校验强行读取。原件保持，不把拒绝称作已经迁移。

## 两条玩家保存边界

- 111归航结果预览后，明确返回营地才由原事务提交钱粮、伤情、成长和武器。营地改名、维修、配装、训练各自经原确认和回读。未确认写入不视作已保存，失败保留待重试状态，不重复领奖；不据此改变普通默认既有编辑与保存流程。
- 出击Esc菜单中的“安全暂存并返回首页”成功后，保存原战场与领取代次；再次继续从暂停恢复。它不是归航，不发搜集奖励，仍需正常巴士集合和结算。

敌人类型、HP、位置/路线、原目标、冲刺/重压剩余前摇，队员状态、救援进度、新同行、携带的武器实例及巴士计时沿既有快照保存。等内容S2/S3仍是不同代次，不能用旧领取请求消费新快照；每份暂存只能领取一次，重开不能重抽战利品或复活死者。

已确认死亡、完整结果、后续营地编辑和训练优先于更早世界。唯一写入者、READY/ACK和原事务链继续使用；本次文档修正没有更改存档协议。

## 已复现的浮点缺陷

历史实现中，一个极小的AI时钟浮点值经JSON编码/解析后在末位交替，记录回读的哈希不幂等，安全暂存被RECORD_READBACK:RECORD_HASH拒绝。历史构建及本轮修改前的单float/真实日志最小例均已复现。拒绝时不应发布失败stage或宣称保存成功；保留现场和原件，不从未发布记录强制恢复。

本分支对新日志增加有版本的精确数值编码，旧有效日志仍按原算法验证且不改原件。公开check保留旧算法二周期对照，同时要求新编码往返和真实日志回读通过。任意外部普通JSON仍可能改变浮点，旧失败stage不会被新算法接受；旧可执行包不支持新日志。总check退出0不是完整P0通过，历史其他WATCH未全部证明同源。详见[兼容合同](../design/p0-record-hash-01.md)。

## 中断仍可能导致旅程不可继续

没有明确成功的新暂存或完整结果就危险退出，或者消费暂存后再次崩溃且没有新暂存/READY，仍可能失去该旅程。退出首页不是回营，不能通过旧营地或旧暂存撤销已确认的阵亡。报错时停止依赖该旅程进行重要推进，保留文件并按原提示处理；本页不提供删除日志、改schema或关闭验证的绕过办法。

本轮公开检查只覆盖[可复测子集](../VALIDATION.md)，完整私有历史档、Windows强杀/锁矩阵、物理OS输入和最终发行可靠性不据此宣称通过。无Release，普通正式生存默认没有切换。

保存协议是Blue Hour工程实现；人数、饥饿、成长和装备策略为 **PROJECT_TEMP**，不是经典Deadly Days原作证据。原作本机精确规则未知项保持UNKNOWN，不新增LOCAL_VERIFIED。
