## 新旧入口分开

M6默认试玩使用固定 `user://playable-v1/run.enemy-v1.json`，声音设置也在该目录。重启继续同一旅程，不产生每次启动的新目录。旧双人开发入口与既有v1–v4到v5的显式迁移/归档边界独立保留；自动测试只使用临时隔离HOME/profile。111不自动转换旧v5/早期隔离档，不把108等旧名册静默改成新规则，也不重抽属性。继续时使用同一隔离目录，不能拿真实玩家唯一原件做测试。

旧途中世界依赖当时的武器、资源、构建及规则指纹，不兼容时明确拒绝。特别是旧武器参数下的暂存须由对应旧包完成；不改版本号或放宽兼容校验强行读取。原件保持，不把拒绝称作已经迁移。

## 两条玩家保存边界

- 111归航结果预览后，明确返回营地才由原事务提交钱粮、伤情、成长和武器。营地改名、维修、配装、训练各自经原确认和回读。未确认写入不视作已保存，失败保留待重试状态，不重复领奖；默认试玩复用同一链，旧开发入口独立保留。
- 出击Esc菜单中的“安全暂存并返回首页”成功后，保存原战场与领取代次；再次继续从暂停恢复。它不是归航，不发搜集奖励，仍需正常巴士集合和结算。

敌人类型、HP、位置/路线、原目标、冲刺/重压剩余前摇，队员状态、救援进度、新同行、携带的武器实例及巴士计时沿既有快照保存。等内容S2/S3仍是不同代次，不能用旧领取请求消费新快照；每份暂存只能领取一次，重开不能重抽战利品或复活死者。

已确认死亡、完整结果、后续营地编辑和训练优先于更早世界。唯一写入者、READY/ACK和原事务链继续使用；PR #4为收据外层增加版本化精确编码，接触任务扩展世界BUILD及表现字段，仍保留原业务schema和这些事务顺序。

## 精确传输与兼容边界

约 9.7e-17 的 AI 时钟值经普通 JSON 往返会在末位交替。新收据使用 BH_EXACT_JSON_V1，将有限 binary64 按 little-endian hex 编码，再认证规范值树；非零相邻值不能合并，两个零和等值 int/float 保持原业务语义。未知版本、非规范编码和坏摘要严格拒绝。详见[编码合同](../design/p0-record-hash-02.md)。

旧未标版本记录只用历史算法认证，原字节和摘要不改；同一链可以追加新记录。新记录认证失败不会退回旧算法，坏旧记录不会被重算修好。TransactionReceipt.same、世界/规则/训练/迁移等嵌入指纹及 binding_version=1 保留原算法，不是全局存档迁移。

旧可执行包不能读取新记录；请为试运行建立独立进度，不能在唯一档上试验降级。引擎原始 JSON 二周期仍由公开诊断复现；该检查现在同时要求新编码十次真实文件往返稳定，另有编码、混合链、容量和畸形记录回归。总 check 退出0仍不代表生产发布获准，其他历史 WATCH 不推定同源。

## 中断仍可能导致旅程不可继续

没有明确成功的新暂存或完整结果就危险退出，或者消费暂存后再次崩溃且没有新暂存/READY，仍可能失去该旅程。退出首页不是回营，不能通过旧营地或旧暂存撤销已确认的阵亡。报错时停止依赖该旅程进行重要推进，保留文件并按原提示处理；本页不提供删除日志、改schema或关闭验证的绕过办法。

公开 check 覆盖[可复测子集](../VALIDATION.md)。Windows 合成矩阵及实际导出包结果另列；完整私有历史档未提供，物理 OS 输入和最终发行可靠性不据此宣称通过。无Release，开发试玩默认已接入，正式生产门禁仍保留。

保存协议是Blue Hour工程实现；人数、饥饿、成长和装备策略为 **PROJECT_TEMP**，不是经典Deadly Days原作证据。原作本机精确规则未知项保持UNKNOWN，不新增LOCAL_VERIFIED。
